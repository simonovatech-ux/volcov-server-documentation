# План безопасной очистки

На сервере остаётся около 19 ГБ свободного места, поэтому срочная очистка не требуется. До удаления нужно восстановить HR-контур, создать свежую резервную копию и проверить её целостность.

## Кандидаты

| Кандидат | Оценка | Рекомендация |
|---|---:|---|
| Неиспользуемый Docker build cache | Docker сообщает 6,1 ГБ reclaimable | Можно очищать после подтверждения; работающие контейнеры не удаляются, но следующие сборки будут медленнее |
| Неиспользуемые Docker-образы | Docker сообщает 11,1 ГБ reclaimable | Удалять поэтапно; часть образов может быть нужна для быстрого rollback |
| Неиспользуемые Docker volumes | Около 690 МБ reclaimable | Не удалять до сопоставления с базами и резервными копиями |
| Остановленный `hiring-app` | Незначительный размер контейнера | Не удалять: это действующий сервис, который сейчас нужно восстановить |
| Остановленный `sber-max-bot` | Незначительный размер контейнера | Удалять только после подтверждения, что `/opt/hiring` полностью его заменил |
| Остановленный `hr-bot-tunnel` | Незначительный размер | Удалять вместе со старым Sber/MAX-контуром после проверки маршрутизации |
| `/opt/hiring-backups` | Около 54 МБ | Ввести retention, сохранить последний рабочий и контрольные снимки |
| `/opt/volcov-offsite-backups` | Около 378 МБ | Не удалять до подтверждения второй копии вне сервера |
| Rollback-каталоги в `/opt` | Менее нескольких мегабайт каждый | Низкий приоритет; удалить после сверки с текущими версиями |
| Архивы `.zip` в `/root` | Менее 100 КБ суммарно | Можно удалить после проверки, что исходники и Git-история сохранены |
| `demo-flow-mcp/.env.new-8756` | Размер незначителен | Проверить назначение; может содержать секреты, не переносить в Git |

Показатели `reclaimable` Docker нельзя просто складывать: слои могут быть общими. Фактическое освобождённое место нужно проверять через `df -h` после каждого этапа.

## Безопасная последовательность

1. Восстановить `hiring-app` и получить HTTP `200` на HR health-check.
2. Сделать свежие дампы обеих PostgreSQL-баз и архивы конфигураций.
3. Проверить контрольные суммы и возможность прочитать архивы.
4. Зафиксировать текущие Docker image IDs для каждого сервиса.
5. Очистить только неиспользуемый build cache.
6. Повторно проверить все health endpoint.
7. Составить список неиспользуемых образов и volumes с привязкой к проектам.
8. Удалять старые образы и резервные копии партиями, с проверкой после каждой партии.

## Что нельзя удалять без дополнительной проверки

- volumes `hiring_pgdata` и `app_postgres_data`;
- volumes Caddy с сертификатами и конфигурацией;
- `/opt/demo-flow-mcp/data`, `/opt/hiring/data`, `/opt/novinki/catalog`;
- рабочие `.env`;
- последний подтверждённый дамп каждой базы;
- образ, на котором работал последний успешный релиз;
- SSH-ключи и `authorized_keys`.

## Команды предварительной проверки

```bash
docker system df
docker ps -a --no-trunc
docker images --digests
docker volume ls
docker inspect VOLUME_OR_CONTAINER
du -xhd1 /opt | sort -h
df -h
```

Команды `docker system prune -a` и `docker volume prune` не следует выполнять без отдельного подтверждения и проверенной резервной копии.
