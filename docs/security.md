# Безопасность и обслуживание

## Обнаруженные риски

### Критично: опубликованный пароль администратора

Пароль `root` был показан на скриншоте. Его следует немедленно сменить, даже если сообщение считается приватным. Новый пароль нельзя добавлять в Git, README или историю команд.

### SSH допускает парольный вход root

Эффективная конфигурация OpenSSH:

- `PermitRootLogin yes`;
- `PasswordAuthentication yes`;
- `PubkeyAuthentication yes`;
- `MaxAuthTries 6`;
- `X11Forwarding yes`.

Fail2ban работает, но зарегистрировал около 12 950 неудачных SSH-попыток и 780 блокировок. После проверки входа по ключу рекомендуется:

1. создать отдельного администратора с `sudo`;
2. запретить парольную аутентификацию;
3. запретить прямой вход `root`;
4. отключить X11 forwarding, если он не используется;
5. сохранить второй активный SSH-сеанс до проверки новой конфигурации.

### Права файла окружения

Большинство `.env` имеют права `0600`. Исключение:

```text
/opt/sber-max-bot/.env 0644 root:root
```

Это позволяет любому локальному пользователю читать файл. Требуемые права — `0600`.

### Обновления и перезагрузка

- доступно около 35 обновлений пакетов;
- существует `/var/run/reboot-required`;
- Ubuntu unattended-upgrades включён.

Обновление и перезагрузку нужно выполнять в согласованное окно, предварительно проверив автозапуск всех Compose-проектов и сделав резервную копию.

### Ограниченная память

На сервере 4 ГБ RAM и нет swap. Для одновременно работающих Node.js, Python/WhisperX и двух PostgreSQL это повышает риск резкого завершения процессов. Рекомендуется настроить небольшой swap-файл и лимиты памяти контейнеров после измерения фактического потребления.

### Неполные health-check'и

Docker health-check настроен только у транскрибера, аудитора и PostgreSQL. Для MCP, Caddy, ботов и Bitrix Plan Autofill следует добавить проверки, чтобы перезапуск контейнера не считался достаточным доказательством работоспособности.

## Положительные меры

- Fail2ban активен;
- базы данных не опубликованы напрямую в интернет;
- административные web-консоли ограничены localhost или контейнерной сетью;
- наружу открыты только `22`, `80`, `443`;
- большинство секретных файлов защищено правами `0600`;
- системные автоматические обновления включены.

## Секреты

В проектах используются учётные данные Битрикс24, MAX, Статосферы, HeadHunter, почты, Cloudflare, LLM/API и PostgreSQL. Документация фиксирует только названия интеграций, но не значения переменных. После публикации пароля администратора разумно провести плановую ротацию наиболее критичных серверных секретов.
